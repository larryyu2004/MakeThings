# Binary search is an interval contract

Binary search fails most often when the loop and its boundaries describe different intervals. Pick a contract first: which indices can still contain the answer? Then every update must preserve that contract and remove at least one candidate.

## Search for an exact value

For a sorted array, `[left, right]` includes both ends. Start with `right = n - 1`; the interval is empty only when `left > right`. If the middle value is too small, all indices through `mid` can be discarded. If it is too large, discard `mid` through the right end.

```cpp
int findIndex(const std::vector<int>& a, int target) {
    int left = 0, right = static_cast<int>(a.size()) - 1;
    while (left <= right) {
        int mid = left + (right - left) / 2;
        if (a[mid] == target) return mid;
        if (a[mid] < target) left = mid + 1;
        else right = mid - 1;
    }
    return -1;
}
```

This works for an empty array too: `right` starts at `-1`, so the loop never reads an element. At exit, `left == right + 1`. With duplicates, the returned matching index is not necessarily the first one.

## Find a boundary instead

For the first element **at least** `target`, use the half-open interval `[left, right)`. Its empty condition is `left == right`, and its answer may be `n` when every value is smaller than the target.

```cpp
int lowerBound(const std::vector<int>& a, int target) {
    int left = 0, right = static_cast<int>(a.size());
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (a[mid] < target) left = mid + 1;
        else right = mid;
    }
    return left;
}
```

For `[1, 2, 2, 4]`, `lowerBound(a, 2)` is `1`, and `lowerBound(a, 3)` is `3`. The key distinction is that `right = mid` keeps a possible answer; `right = mid - 1` would throw it away. Both loops take `O(log n)` time and `O(1)` extra space. The sorted-input precondition is essential: neither version works on an arbitrary unsorted array.

## A useful check

Before coding, write down the interval, the loop condition, and what the final pointer means. Test empty input, one item, duplicates, and targets below and above the data. These cases expose boundary mistakes faster than a large random example.
