# 用前缀和频率统计目标区间

旧版 [LeetCode 560](https://leetcode.com/problems/subarray-sum-equals-k/) 笔记只有题目与两个例子，还没有推导算法。关键一步是把连续区间之和转化成两个前缀和之差。

## 把区间变成差值

令 `prefix` 表示当前位置之前所有元素的和。如果某个更早的前缀值为 `prefix - k`，那么从它之后到当前位置的元素之和就是 `k`。符合条件的早期位置可能不止一个，因此要保存每个前缀值的**出现次数**，而不只是最后一次出现的位置。

先让映射含有 `{0: 1}`，代表数组开始前的空前缀，才能计入从下标零开始的区间。遍历时先更新累加和，把此前值为 `sum - k` 的前缀数量加入答案，最后记录当前前缀，供后续位置使用。

```cpp
long long countSubarrays(const std::vector<int>& nums, int k) {
    std::unordered_map<long long, long long> seen{{0, 1}};
    long long sum = 0, answer = 0;
    for (int value : nums) {
        sum += value;
        auto it = seen.find(sum - k);
        if (it != seen.end()) answer += it->second;
        ++seen[sum];
    }
    return answer;
}
```

对 `[1, 1, 1]`、`k = 2`，符合条件的是下标 `0..1` 与 `1..2`，共两段。对 `[1, 2, 3]`、`k = 3`，则是 `[1, 2]` 与 `[3]`。

## 更新顺序为什么重要

必须在将当前前缀加入 `seen` **之前**统计匹配，否则当 `k = 0` 时，当前前缀会与自己匹配，把空区间算进去。题目允许负数，因此普通的收缩式滑动窗口不可靠：加入一个新元素后，区间和也可能下降。前缀频率法可以统一处理正数、零和负数。

哈希映射下，期望时间为 `O(n)`，最坏额外空间为 `O(n)`。代码用 `long long` 保存累加和和答案，降低溢出风险；实际接入时仍应按使用环境的输入范围及函数接口选择返回类型。
