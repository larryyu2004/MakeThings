# C++ 中什么时候可以移动一个值

复制持有资源的对象可能有较高开销。我以前的左值、右值笔记试图解释 C++ 何时能复用资源，却把表达式类别简化成“右值没有身份”之类的规则。更可靠的问题是：**当前表达式属于哪一类，它的类型又支持哪些操作？**

## 表达式、引用与名称

左值表达式标识一个对象或函数；`std::string("new")` 这样的纯右值计算一个值；`std::move(name)` 这样的将亡值标识一个资源可被复用的对象。这些是表达式的类别，并非永久贴在变量上的标签。即使变量类型是右值引用，只要通过变量名使用它，该表达式仍是左值。

```cpp
#include <string>
#include <utility>

std::string name = "Ada";
std::string copy = name;             // name 是左值表达式
std::string moved = std::move(name); // std::move(name) 是将亡值
name = "Grace";                      // 可以重新赋值
```

`std::move` 只执行类型转换；真正转移资源的是随后选中的移动构造或赋值操作。标准库对象被移动后仍然有效，但其具体值可能没有保证，因此不能假设 `name` 一定变成空字符串。移动也不总会发生：`const` 对象通常无法匹配接收非常量右值引用的移动构造函数。

## 先设计接收参数的接口

函数只读取值时，可以使用 `const T&`；需要修改调用者对象时使用 `T&`；需要获得自己的值且可接受复制或移动时可以按值接收 `T`。明确的 `T&&` 可以表达“消费”操作，但实现必须遵守这个所有权约定。在泛型代码中，推导得到的 `T&&` 是转发引用，`std::forward<T>(value)` 可以保留调用者原来的表达式类别。因为 `value` 有名字，直接传它时传出的是左值。

<Key>移动是交给接收操作的一种可能性，并不是保证发生资源转移的命令。</Key>

这样分析性能才更准确：先看该类型实际选择了哪个构造函数，再测量避免复制是否有意义。清楚的所有权语义比到处添加 `std::move` 更重要；尤其在返回语句中，随意添加它还可能妨碍复制消除。
