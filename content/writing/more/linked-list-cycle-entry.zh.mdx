# 快慢指针为什么能找到环入口

[LeetCode 142](https://leetcode.com/problems/linked-list-cycle-ii/) 要找出链表进入环的节点；如果没有环，就返回 `nullptr`。记录所有访问过的节点当然可行，但需要线性空间。Floyd 快慢指针只用两个指针和一段距离推导。

## 先判断是否有环

让 `slow`、`fast` 都从头节点出发，每轮分别走一步和两步。如果 `fast` 遇到空指针，链表有终点。如果两者相遇，就存在环：进入环后，它们的相对距离每轮按环长取模变化一步，因此最终必然重合。

## 再找入口

设头节点到环入口的距离为 `a`，入口到相遇点为 `b`，相遇点回到入口还要走 `c`。相遇时慢指针走了 `a + b`，快指针走了它的两倍。两者路程之差是整数个环长 `k(b + c)`，所以 `a + b = k(b + c)`，即 `a = k(b + c) - b`。因此 `a` 与 `c` 对环长取模相同。一个指针从头开始，另一个从相遇点开始，都每轮走一步，便会在入口相遇。

```cpp
// LeetCode 提供带 next 指针的 ListNode。
ListNode* detectCycle(ListNode* head) {
    ListNode* slow = head;
    ListNode* fast = head;
    while (fast && fast->next) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) {
            ListNode* fromHead = head;
            while (fromHead != slow) {
                fromHead = fromHead->next;
                slow = slow->next;
            }
            return fromHead;
        }
    }
    return nullptr;
}
```

空链表或没有自环的单节点链表返回空；单节点自环则返回该节点。算法不修改链表。两阶段总计 `O(n)` 时间、`O(1)` 额外空间。直接使用这段推导，也省去了旧稿中的额外“锚点”状态与难以检查的移动逻辑。
