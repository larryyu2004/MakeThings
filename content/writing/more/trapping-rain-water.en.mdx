# Trapping rain water: from boundaries to two pointers

For [LeetCode 42](https://leetcode.com/problems/trapping-rain-water/), the water above position `i` is determined by the tallest wall at or before `i` and the tallest wall at or after it. Its depth is `min(leftMax[i], rightMax[i]) - height[i]`. The minimum matters: water spills over the shorter side.

## Start with arrays

Compute a left-to-right maximum array and a right-to-left maximum array. For heights `[2, 0, 2]`, both walls reach height `2`, so the middle stores `2` units. Sum the formula across positions. This solution is easy to reason about and takes `O(n)` time and **`O(n)` extra space** for the two arrays. The old draft labelled its space `O(1)`, which overlooks those arrays.

## Remove the arrays

Two pointers can keep only the best boundary seen from each side. At every step, process the side with the smaller known maximum. The other side already has a boundary at least that high, so the processed side determines the water level there.

```cpp
int trap(const std::vector<int>& height) {
    int left = 0, right = static_cast<int>(height.size()) - 1;
    int leftMax = 0, rightMax = 0, total = 0;
    while (left < right) {
        leftMax = std::max(leftMax, height[left]);
        rightMax = std::max(rightMax, height[right]);
        if (leftMax <= rightMax) {
            total += leftMax - height[left];
            ++left;
        } else {
            total += rightMax - height[right];
            --right;
        }
    }
    return total;
}
```

For an empty input, `right` is `-1` and the loop is skipped. For `[3, 0, 1, 3]`, the interior depths are `3` and `2`, giving `5`. The algorithm uses `O(n)` time and `O(1)` extra space.

## A third way to view it

A decreasing stack of indices identifies a basin when a taller right wall arrives. Popping the basin floor reveals a left wall; `width × bounded height` adds one horizontal layer of water. Each index enters and leaves the stack at most once, so this also takes `O(n)` time, but needs `O(n)` extra space. The array, pointer, and stack approaches measure the same bounded area from different directions.
