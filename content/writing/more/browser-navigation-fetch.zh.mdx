# 导航、表单和 fetch 是不同的浏览器请求

浏览器可能因为多种原因请求同一个 URL。如果把它们都称为“打开页面”，旧版网络笔记中的例子就容易混淆。需要先看是谁发起请求：用户导航、HTML 表单提交、资源元素加载，或 JavaScript 调用 `fetch()`。

## 相同目标，不同结果

点击普通链接通常会导航当前文档。提交表单也可能导航。使用 `method="get"` 时，成功提交的控件值会编码进 URL 查询参数；使用 `method="post"` 时，数据进入请求体，编码方式由 `enctype` 决定。按照浏览器导航规则，服务器响应可能成为新的文档。

`fetch()` 从 JavaScript 发出请求，并把 `Response` 对象交给代码。即使响应内容是 HTML，它也不会因此自动替换当前页面。下面的代码可以在浏览器控制台运行，请求当前站点的首页并输出状态；运行它的站点需要提供 `/` 路由。

```js
const response = await fetch("/");
console.log(response.status);
```

跨源请求还受 CORS 等浏览器规则约束：若服务器未允许，JavaScript 可能无法读取响应。普通页面导航遵循另一套安全路径。`<img>` 等资源元素也能自行发起请求，无须页面代码调用 `fetch()`。

打开浏览器网络面板，对比方法、发起者、目标、标头、响应和重定向。真实记录比“一个 URL 总对应一种请求”更能解释行为。关于 URL 与响应的完整过程，见[从 URL 到页面资源](/zh/writing/url-to-resource)。
