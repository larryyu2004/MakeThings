# Backtracking needs deduplication at each depth

[LeetCode 491](https://leetcode.com/problems/non-decreasing-subsequences/) asks for distinct non-decreasing subsequences of length at least two. Subsequences preserve input order but may skip elements. Repeated values create a trap: two choices at the same recursion depth can generate identical value sequences.

## Separate two rules

The current path enforces order and monotonicity: a candidate must come after the previous index and be at least as large as the path's last value. A fresh `used` set inside each recursive call enforces uniqueness **among sibling choices**. It must not be shared globally: in `[4, 6, 7, 7]`, one branch can legitimately use both sevens to form `[4, 7, 7]`, even though a sibling branch choosing the other seven first would duplicate `[4, 7]`.

```cpp
std::vector<std::vector<int>> findSubsequences(
    const std::vector<int>& nums) {
    std::vector<std::vector<int>> answer;
    std::vector<int> path;
    auto visit = [&](auto&& self, int start) -> void {
        if (path.size() >= 2) answer.push_back(path);
        std::unordered_set<int> used;
        for (int i = start; i < static_cast<int>(nums.size()); ++i) {
            if ((!path.empty() && nums[i] < path.back()) ||
                !used.insert(nums[i]).second) continue;
            path.push_back(nums[i]);
            self(self, i + 1);
            path.pop_back();
        }
    };
    visit(visit, 0);
    return answer;
}
```

For `[1, 2, 2]`, the valid distinct results include `[1, 2]` once and `[1, 2, 2]` once. Sorting first would destroy the original subsequence relation, so this approach works directly on input order.

## Cost of enumeration

There can be exponentially many candidate subsequences. Traversal is bounded by `O(n × 2^n)` time when copying paths into output is included; the recursion path, stack, and per-depth sets take up to `O(n^2)` auxiliary space in the general-value version, excluding results. The old draft's `O(n)` space claim missed the simultaneously live sets. If the problem's bounded value range is used, a fixed-size `used` array per depth changes the precise bound but not the need to count those live arrays.
