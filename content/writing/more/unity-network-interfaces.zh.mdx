# 为 Unity 局域网发现选择地址

多人游戏客户端需要的是**自己能够到达的地址**，而不只是主机设备拥有的某个地址。旧版 Unity 笔记讨论了遍历网络接口与发送发现消息。更重要的经验是：一台电脑或手机可能同时拥有 Wi-Fi、热点、VPN、蜂窝网络、回环和虚拟网络接口。

## 发现消息能证明什么

主机可以在局域网内广播游戏端口。如果客户端收到消息，数据包的发送方地址通常比从主机接口列表中随意挑出的地址更适合作为连接候选。客户端仍需验证消息，再尝试真正的游戏传输层连接。收到发现包既不证明游戏端口可达，也不代表会话已经建立。

设备切换网络后，地址可能改变。手机热点的路由方式或客户端隔离设置，也可能与共用 Wi-Fi 接入点不同。因此，硬编码常见私网网段，或者直接采用第一个 IPv4 地址，都不可靠。

## 更稳妥的流程

先启动游戏监听，再发布发现消息。消息只需包含协议版本、会话标识、显示名称和游戏端口等少量信息。客户端应让过期候选主机消失，并分别呈现“搜索中”“已发现”“连接中”和“已连接”的状态。广播无法到达时，可以提供手动输入地址的方式。

<Key>网络接口只提供候选地址；传输层连接成功，才是这条网络路径可用的证据。</Key>

以上是架构示意，不是可直接复制的 Unity API 教程。Socket 权限和广播行为仍需在目标平台及实际网络环境中测试。
