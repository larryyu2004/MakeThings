# 用分层模型理解一次 Web 请求

“浏览器发送 HTTP 请求”是一种方便的简写，却隐藏了几项不同的工作。旧版网络笔记罗列过层次与协议；现在更有用的读法，是沿着一次请求追问各部分负责什么。

假设浏览器访问 `https://example.com/article`。它需要先找到主机可用的地址；DNS 通常提供这一信息，但已有缓存时未必需要重新查询。然后浏览器根据 HTTP 版本和服务器建立合适的连接。在应用层，HTTP 为请求定义方法、目标、标头以及可能存在的请求体；服务器返回状态、标头和内容。

## 其他层提供什么

传输层负责端点之间的通信。TCP 提供有序字节流，其他传输方式则有不同特性。IP 负责跨网络寻址和传送数据包，本地链路技术负责把数据送到下一跳。路由器改变下一跳，并不会改变浏览器要访问的 HTTP 资源。

这是一种教学模型，并不表示每次请求都会依照完全相同的五个盒子依次发生。HTTPS 还涉及 TLS；代理、缓存和现代 HTTP 的传输实现也会影响实际过程。浏览器可能复用连接，缓存也可能在无需联系源服务器时返回内容。分层模型的价值是帮助定位问题：域名无法解析、连接失败、HTTP 错误状态和页面内容无效，是不同类型的故障。

应用层的完整例子可以接着读[从 URL 到页面资源](/zh/writing/url-to-resource)。

<Key>先用层次判断故障由谁负责，再用浏览器或网络工具核对这次真实请求。</Key>
