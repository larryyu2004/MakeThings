# 探索 RISC-V 上的 xv6 内核

理解操作系统内核，可以先从一个问题入手：**进程访问某个地址时会发生什么？**原来的 xv6 笔记收集了 RISC-V、虚拟内存和缺页异常的许多知识点。这里按用户虚拟地址到物理页的路径重新组织，再说明写时复制与延迟分配如何利用这条路径。

## xv6 中的地址转换

RISC-V 的 Sv39 机制通过三级页表转换虚拟地址。页表项（PTE）可以指向下一级，也可以映射一个页；标志位描述可读、可写、可执行以及用户态是否可访问等权限。转换后备缓冲区会缓存近期结果；修改映射后，可能需要执行适当的 `sfence.vma`，让处理器使用更新后的页表项。

```text
用户虚拟地址
  → Sv39 页表遍历
  → 物理页（映射有效且权限允许时）
  → 缺页异常（映射或权限不满足时）
```

<Key>虚拟地址只是进程地址空间中的一个名称，并不保证这个地址已经分配了物理内存。</Key>

每个进程都有自己的用户页表，xv6 还维护内核页表。trampoline 的映射使陷入与返回代码能够在用户态和内核态上下文切换时运行。把两种页表的职责说清，比笼统地说它们总是“合并”为一张表更准确。

## 缺页异常让内存策略成为可能

用户指令访问未映射的页，或违反页表项权限时，硬件会触发缺页异常。内核查看出错地址和原因，再决定修复映射还是结束进程。有效的延迟分配堆地址、写时复制页面和非法地址，不应得到相同的处理。

在**延迟分配**中，`sbrk` 可以先扩大用户地址范围，而不立即映射物理页。首次有效访问触发异常后，处理程序分配并清零页面、建立用户映射，然后重试指令。这样可以省去从未使用的预留内存的分配成本，但首次访问会多一次异常处理。

在**写时复制 fork** 中，父子进程最初通过只读映射共享物理页。某一方写入共享页时，异常处理程序创建私有副本，更新该进程的页表项为可写映射，再继续执行。引用计数很重要：如果另一进程仍映射着页面，就不能提前释放物理页。

```text
fork：共享页面 → 清除写权限 → 记录引用
写入异常：确认是写时复制页 → 必要时复制 → 更新 PTE → 重试
退出或取消映射：最后一个引用消失后才释放物理页
```

这些是教学项目中可以实现的扩展功能，不能假定每个原版 xv6 都自带。具体文件和行为取决于课程版本与项目修改。

## 避免把教学模型当作硬件定律

RISC-V 是指令集架构；“五级流水线”是常见教学模型，不是所有 RISC-V 处理器的固定结构。同样，64 位机器不代表每条指令都是八字节：常见 RISC-V 指令为 32 位，压缩指令扩展还支持 16 位指令。程序计数器如何变化取决于具体指令与控制流。

交换空间也要单独说明。支持虚拟内存不表示 xv6 会自动把页面换出到磁盘；要实现这种行为，还需要缺页处理和后备存储策略。

## 我的收获

页表提供机制，内核的异常处理程序决定策略。只要明确地址范围、PTE 权限、物理页所有权以及指令重试路径，写时复制和延迟分配就是同一地址转换流程的两种清晰变体。
